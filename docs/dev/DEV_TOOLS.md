# Dev tools reference

Everything a developer or agent uses to run, inspect and test the game locally: URL parameters, the in-game dev console, dev-only pages and REST routes, the mock blockchain, environment variables, debug handles and test commands. Dev tools are **dev-only** (not anti-cheat, D-25): a production build never mounts the console, and the `/v1/dev/*` routes answer 404 there (`DevOnlyGuard`); the dev pages (`/dev/chain/`, `/dev/parity/`) are still built, but their data routes are those `/v1/dev/*` routes.

Start the stack with `npm run dev` (Postgres in Docker + app + Vite). Ports come from `TA_PORT_BASE` (default 4000): app `base+1` (4001), client `base+1173` (5173). A wave or issue worktree pins its own base in a gitignored `infra/.env.worktree`, so check that file for the URL (e.g. the W00 worktree uses 4101 / 5273).

## Dev console

Open with the **`` ` ``** key (the key under Esc on any layout; click the game first if DevTools has focus). Enter runs a command, ↑/↓ walk the history, Esc closes; commands typed while one runs are queued. It is **not** the browser's DevTools console. Only commands of enabled waves exist: `help` lists them.

| `ping` | No-op sim command; prints the tick it was applied at | both |

**Adding a command:** a client feature (`frontend/game/features/<id>/index.ts`) lists it in `devCommands` (`{ name, help, run(args, ctx) }`); it can send sim commands (`ctx.services.sendCommand(kind, args)`), server dev commands (`ctx.services.devServer(name, args)`) or ask the host's ledger (`ctx.services.ledgerQuery(account, limit)`). A server dev command registers in `DevCommandRegistry` (`backend/app/src/dev/`) with `defineDevCommand({ name, help, args: zod, run })`. The game rule itself goes in `shared/sim` (D-31).

## HUD and overlays (online flow)

- `TICK` chip (top left), `×k` warp badge under it.
- **Minimal HUD / Family Resource Bar** (top centre, W01/W02): tight-to-top unified bar with colony name, `MM:SS` game clock, family stock & caps (`Metals`, `Minerals`, `Bio`, `Supply`; subtle green highlight when net increasing, subtle red highlight when net decreasing, none when flat; red at cap; hover for T1/T2/T3 breakdown plus live `Income: +X/s`, `Spending: -Y/s`, and `Net: +Z/s`), HQ power cell bar (`800 / 800 E`; `— E` until a view carries the HQ; hover for cell & grid power breakdown), and command reject toasts (one per reject cause, worded per command kind; no shortfall numbers: the sim never rejects for cost, an unaffordable Hub is accepted and its order waits, GP-30; toasts are buttons, announced politely to screen readers).
- **Selected Unit / Building / Deposit Bar** (bottom centre, W01/W02): compact horizontal bar hidden when nothing is selected and cleared on empty-ground click; includes a multi-select unit grid + selection count badge (`data-testid="selection-grid"`, `selection-count`), hull HP bar, HQ power cell bar (when HQ is selected), blue active progress bar (`0 < progress < 1`), current job (`idle`, `moving`, `working`, `constructing`, `waiting`), queue count, and `CANCEL JOB` button (sends `cancelTask { taskId: 'harvester:<id>' }`: ends the unit's job, its terraform order and terraform chain; `50%` refund of spent resources; the `X` key only stops the unit, FF-40). Left-click selects the **HQ**, **Harvester**, **Buildings**, or **Resource Deposits** (displaying deposit type, `FULL`/`HALF`/`DEPLETED` visual stage, and `remaining / 500` reserves); right-click (or Shift+left-click) orders `moveUnit` for movable units (right-clicking a deposit with a Harvester or HQ paths to an adjacent hex `hexDistance === 1` and harvests without stepping inside the deposit; up to 6 harvesters can work the same deposit); **X** stops the selected unit (`stopUnit`). Visible units and working buildings also render 3D overhead HP and blue (`0x38bdf8`) progress bars (`unit-health-bars`). Server ingress: more than 20 commands/s (bursts of 40) per player are rejected `rate_limited`.
- **Command Dock** (bottom left, W01/W02): single collapsible (`HIDE` / `SHOW`) tabbed panel consolidating **Build (`[B]`)**, **Production (`[U]`)**, **Terraform (`[T]`)**, and **Queue** (`[Q]` collapses/expands the queue lane):
  - **Build (`[B]`)**: W02 Construction menu (`Command Hub`, `Metals Extractor`, `Solar Collector Array`) with 3D hex footprint ghost (`construction-ghost-3d`), tile occupancy + deposit checks, `R` rotation, left-click map placement, and right-click / **Esc** cancel (W01: `Command Hub [H]` with `hub-ghost-3d`). Resources are deducted progressively by construction progress.
  - **Production (`[U]`)**: Units menu (`Harvester Drone`, batch `1`–`5`, `REPEAT`, `QUEUE`, and `HUB BUFFER` with progressive resource deduction).
  - **Terraform (`[T]`)**: 3-button toolset for the **HQ Drone** and **Harvester** (a selected own, alive HQ Drone / Harvester works the order, else the host picks the nearest worker), top to bottom. The keys `G` / `R` / `Z` arm a tool only while the Terraform tab is open and the dock expanded; closing or switching the tab disarms it. One map click sends one order and disarms the tool (a click the preview refuses keeps it armed); right-click disarms and still reaches the map (a unit move is not swallowed); Esc disarms.
    - `TERRAFORM [G]`: click a terraformable hex (trees, rock, slope, crater, uneven or wild ground; no building, deposit or foreign hex; before the first Hub only within `preHubTerraformRadius` of the pod; preview = `groundPreview.ts`, same rule as the sim) → the worker walks there, flattens it (terrain `flat`, prep `prepared`: passable and buildable, drawn as plain ground) and then **keeps going on its own** to the obstacle hex (forest, rock, slope, hole, uneven ground; never level grass) the colony may terraform that is **closest to the hex you clicked** (ties: closest to the hex it just finished), so it clears the area around your click ring by ring instead of following a line of trees away from it, until none is left. A follow-up it cannot reach yet (e.g. inside a forest) is skipped silently and tried again after the next finished hex. Unreachable follow-ups are skipped silently (only the clicked hex reports `no_path`). `moveUnit` / `stopUnit` (right-click, `X`), a new TERRAFORM order for that unit or `cancelTask` (unit card `CANCEL JOB`) ends the chain; a REPAIR for that unit queues behind its current hex and the chain resumes. The status line follows the chain (e.g. `TERRAFORM TREES (9,-7) 18% · hex 2`) and says when it ends. Sent as `enqueueTask { terraform: { op: 'work', intent: 'terraform', tiles: [{q,r}], workerId? } }`.
    - `REPAIR [R]`: click a damaged own unit/building → repaired at 40% of its base build cost for a full repair (`REPAIR_COST_RATE`, `intent: 'repair'`, paid progressively; nothing is sent when nothing on the hex is damaged). While a building ghost is up, `R` rotates the ghost instead.
    - `DISMANTLE [Z]`: dismantles any friendly unit or building except HQ / Command Hub and refunds 50% of spent resources (`DISMANTLE_REFUND_RATE`). `X` only stops the selected unit.
    - Yields (one tunable table for every path, `opsBasic.<op>.yields`): Trees `+15 Biomass`, Rock `+8 Metals, +4 Minerals`; buried deposits are revealed; then each finished hex rolls a **1% resource find** (data row `terraformFinds.deposit`, `shared/sim/src/data/terraform-finds.ts`; `tune terraformFinds.deposit.chance 1` makes every finished hex find one; `spawndeposit` places one directly): a full deposit (metals / minerals / oil, uniform) of tier **t1 50% / t2 35% / t3 15%** appears on the hex (tile layer `depositTier`, event `resourceSpawned` → toast `Resource found: Light Alloys (T2) deposit at (q, r)`; the deposit card title shows `· T<n>`; a Harvester or Extractor on it yields `metals.t{n}` / `minerals.t{n}` / `bio.biomass|bio.t2|bio.t3`; depleted, it stays as rubble).
    - Embedded reference tables built from sim data (`referenceTables.ts`: times, yields, resource find, Harvester / Extractor / Solar rates), rebuilt after a `tune`. No hex highlight, no Ctrl multi-select, no area brush.
  - **Queue**: Construction + Units lanes with wait reason (`resources`, `site`, `power`, `builder`, `storage`), ETA, per-item cancel and `CANCEL ALL (50% REFUND)` (returns 50% of spent resources when in progress), and reorder.
- **Planet clock** (top resource bar, right after the energy chip, W02): sun/moon phase icon, planetary clock (`HH:MM`) and daylight % of your colony (`shared/daytime.ts`). **Power widget** (top right, W02): only when relevant: red `BROWNOUT — SHEDDING GROUP n · N E/s OFFLINE` banner when demand exceeds supply, and an inspector for the first shed building (`OFFLINE: BROWNOUT`). The grid balance (`+supply / −requested demand E/s`, requested = before shedding) is in the energy chip's hover; the chip itself is the HQ power cell, not the grid (FF-47, FF-50).
- **WAVES** flag panel (top right): one chip per wave, on/off, and the flag source; collapsible. Below it: `BORDER: SOLID / HATCH` toggle (W01; the choice is remembered per browser in `localStorage` `terra.borderHatch`).
- **Net stats** overlay (bottom right, dev only): prediction mode (on / off / auto-off), pending commands, rollbacks, last correction in tiles (the largest jump a confirmed view applied to an already drawn, predicted pose), worker step p95.
- "Connecting…" / "Reconnecting…" / "still trying" banner (top centre) while the socket is down.
- The last picked tile is kept in `window.__online.lastPick` (`q, r, i`; picks are not logged to the console).

## Mock blockchain (NEAR phase 1, D-30)

All NEAR features run on **mock adapters** behind abstract ports (`backend/app/src/near/application/ports/`). Mocks keep their state in Postgres tables `chain.mock_chain_*`, return `ChainReceipt`s with `mock:`-prefixed hashes, wait 300–1 500 ms and can inject failures. Details: [`backend/app/src/near/README.md`](../../backend/app/src/near/README.md).

- **Mocks today:** `ChainReadPort` (receipts, health, `chain.ping`) and `BadgeNftPort` (NEP-171, idempotent by `opId`). Every other port's mock lands with its feature wave.
- **Chain outbox:** every chain write is queued in `chain.chain_outbox` in the same transaction as the game change and relayed with retry/backoff; deterministic `opId`s make retries safe.
- **Explorer:** `/dev/chain/`. Contract tests: `npm run test:contract` (mocks), `npm run contract:real -- --port X` (real adapters, from W23).
- **Selection:** `NEAR_ADAPTER_<PORT>=mock|testnet|mainnet` (anything but the exact strings `testnet`/`mainnet` means mock), `AI_PROVIDER`, `NOTIFY_ADAPTER`. Production refuses mocks unless the matching `*_ALLOW_MOCK_IN_PROD=true` is set, and boot names every mocked port.

The landing site is the planet's own sim's answer (`nextLandingSite`); an existing home's planet is loaded (restored from its snapshot) before `ACTIVE` is answered, 503 `HOME_UNAVAILABLE` when it cannot be (held). | `GET /v1/dev/planets` | Loaded planet ids |

## Environment variables

Real environment wins over `infra/.env.worktree`, which wins over `infra/.env` (template: [`infra/.env.example`](../../infra/.env.example)). Only the exact string `true` turns a boolean flag on (exception: `AI_LIVE=1`). An invalid value aborts boot and names the variable.

|---|---|---|
| `TA_PORT_BASE` / `PORT` | 4000 / base+1 | Port base for app, client, e2e |
| `TA_PG_PORT`, `TA_DB_NAME`, `DATABASE_URL` | 15434, `terraagent` | Shared dev Postgres, one database per worktree |
| `TA_HOST`, `CORS_ORIGINS` | 127.0.0.1, — | Bind address; extra allowed web origins |
| `JWT_ACCESS_SECRET` | dev literal (not in production) | HMAC secret for access JWTs (≥ 16 chars). Production refuses to boot without it or with the public dev default |

| `LOG_LEVEL`, `LOG_LEVELS` | info | pino level; per layer, e.g. `sim=warn,http=info` |
