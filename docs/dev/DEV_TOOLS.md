# Dev tools reference

Everything a developer or agent uses to run, inspect and test the game locally: URL parameters, the in-game dev console, dev-only pages and REST routes, the mock blockchain, environment variables, debug handles and test commands. Dev tools are **dev-only** (not anti-cheat, D-25): a production build never mounts the console, and the `/v1/dev/*` routes answer 404 there (`DevOnlyGuard`); the dev pages (`/dev/chain/`, `/dev/parity/`, `/dev/mock-oauth`) are still built, but their data routes are those `/v1/dev/*` routes.

Start the stack with `npm run dev` (Postgres in Docker + app + Vite). Ports come from `TA_PORT_BASE` (default 4000): app `base+1` (4001), client `base+1173` (5173). A wave or issue worktree pins its own base in a gitignored `infra/.env.worktree`, so check that file for the URL (e.g. the W00 worktree uses 4101 / 5273).

**Combat Lab (`F6`, or the `COMBAT F6` button in the top-right HUD, W07):** choose an entity type, edit a value, then click that row's **APPLY**. Opening the panel selects the currently selected game entity's type when available. Changes apply live to every entity of that type on the current planet through the existing `tune` service, on both server and `?host=local`; other clients receive the same balance update. Controls include maximum health, movement speed, sight, damage, attacks per second, range, minimum range, projectile speed and splash radius where the type supports them. Health edits preserve each living entity's current health percentage. Distances use hex tiles (2 m), speed uses tiles/second, and fire rate uses attacks/second (up to 5). Insects expose attack interval in seconds, stepped by the 0.2-second sim tick and bounded by each species’ shared windup/release/recovery timing (0.8 s for ants, 1 s for beetles/spitters). Demo Tank/Artillery entries expose weapon settings only. **RELOAD VALUES** reads the latest host data; **EXPORT JSON** selects the planet's merged balance overrides for copying. F6/Escape closes the panel; F8 remains the visual lab and F9 remains CRT. The game continues simulating while the panel owns gameplay input.

## Mock blockchain (NEAR phase 1, D-30)

All NEAR features run on **mock adapters** behind abstract ports (`backend/app/src/near/application/ports/`). Mocks keep their state in Postgres tables `chain.mock_chain_*`, return `ChainReceipt`s with `mock:`-prefixed hashes, wait 300–1 500 ms and can inject failures. Details: [`backend/app/src/near/README.md`](../../backend/app/src/near/README.md).

- **Mocks today:** `ChainReadPort` (receipts, health, `chain.ping`) and `BadgeNftPort` (NEP-171, idempotent by `opId`). Every other port's mock lands with its feature wave.
- **Chain outbox:** every chain write is queued in `chain.chain_outbox` in the same transaction as the game change and relayed with retry/backoff; deterministic `opId`s make retries safe.
- **Explorer:** `/dev/chain/`. Contract tests: `npm run test:contract` (mocks; `--port identity,relayer` is a case-insensitive comma list, and an empty `--port` runs every suite), `npm run contract:real -- --port X` (real adapters, from W23).
- **Selection:** `NEAR_ADAPTER_<PORT>=mock|testnet|mainnet` (anything but the exact strings `testnet`/`mainnet` means mock), `AI_PROVIDER`, `NOTIFY_ADAPTER`. Production refuses mocks unless the matching `*_ALLOW_MOCK_IN_PROD=true` is set, and boot names every mocked port.

| Command | Does |
|---|---|

| `profile export --id <p>:<v> [--out f]` | the portable profile content and ref |

| `simulate --manifest f\|-` | submit only: returns an experiment id (idempotent: default requestId is the manifest hash) |

| `activate --version <p>:<v> --expected-previous <p>:<v>\|none [--effective-tick n] [--evidence-run id] [--non-production]`, `rollback --id <activation>` | operator only (activate token) |

Exit codes (ECONOMY §6): `0` ok (also queued/running/cancelled status), `2` invalid input and every 4xx including 401/403 (the AI token on `activate`/`rollback` is 403, so exit 2), `3` completed with failing gates or a `compare` gate regression, `4` execution failure (5xx, unreachable API, `failed` or `incomplete` experiment).

**Comparison and recommendation (W13-48).** Statistics are exact: paired differences per seed, Student t 95 % interval (`shared/sim/src/economy/experiments/stats.ts`), no floats and no random draws; one seed gives `insufficient_data`, never a zero-width interval. Manifest `heldOutSeeds` (disjoint from `seeds`) run like `seeds` but only confirm: the improvement must not reverse on them. Dimensions (`metric-dimensions.ts`): retention, progression, affordability, trading depth, inventory growth, net contribution (platform revenue); no scalar score. `recommend` refuses when: a hard gate fails; a gate regresses; any dimension is worse (tuning, held-out or stress); the only improvement is platform revenue/fees; the improvement holds only on a subset of seeds (not worse on any seed and better on at least 3 of 4); held-out seeds disagree or are absent (`insufficient_evidence`); a demand-sensitivity case fails. `--sensitivity` takes `[{label, baselineId, candidateId}]` of experiments re-run with `sensitivityManifests(manifest)` (budget x0.5/x1/x2). Gates are versioned data in `gate-catalog.ts` (hard invariants plus economic calibration hypotheses, all `approved: false`). `cashApproval` is always false in W13: it needs every gate approved and passing on tuning, held-out and stress runs plus an external pilot reference, and the API accepts none.
