# CLAUDE.md

TerraAgent: autonomous colony builder (Vite + TypeScript + Three.js). Read [`AGENTS.md`](./AGENTS.md) first. It holds the mandatory 3D visual rules (4 pillars), skill routing for `.agents/skills/*`, and the page/UI rules. [`README.md`](./README.md) has the page list, URL parameters and controls.

## Commands

```bash
npm run dev        # http://127.0.0.1:5173/  (hub page; links to everything)
npm run typecheck  # tsc --noEmit
npm run build      # typecheck + check:structure + vite build → frontend/dist/ (must stay warning-free apart from chunk size)
npm run check:structure  # fails on any file > 500 lines or function > 100 lines (frontend/, scripts/)
npm run wave       # open/resume the next ready wave in its worktree and start its runner there (claude, agy, or grok; `--runner` overrides); `-- status`, `-- validate NN` (2-iteration pre-landing review & fix), `-- land NN` (Mode 1), `-- sync NN` (Mode 2), `-- audit NN`, `-- propagate NN`
npm run wave:land -- <NN>                                # Mode 1 ("merge wave into main"): 3-iteration audit/test/E2E loop, auto-heal generated conflicts, merge --no-ff to main, tag wave-NN, push, cleanup + future-wave propagation
npm run wave:sync -- <NN|--all> [--sync-issues]          # Mode 2 ("merge main into wave"): merge updated main into WIP wave worktree (and active issue/WNN-XX worktrees) with 3-iteration verification & incoming plan delta
npm run wave:audit -- <NN> [--sync] [--json]             # semantic collision scan (ECS codes, migrations, Q&L/Decision IDs, unlanded issues) + as-built scope delta
npm run wave:propagate -- <NN> [--add-issue WMM ...]     # post-merge self-review feature audit & safe issue injection when wave plans exist
npm run validate:wave -- <NN> [--gates] [--strict]       # pre-landing wave validator (task parity, Test Pyramid [unit+integration+backend E2E + pos/neg/corner cases], AST duplication, orchestrator/service split, client+server wiring)
npm run test:wave:validator                              # self-test of the pre-landing wave validator
npm run validate:models -- <id|--category robot|--all>   # geometry validator for kitbash models
npm run test:models                                    # self-test of that validator
npm run validate:particles -- <--all|id|targetKind>    # validator for 3D interaction particle presets
npm run test:particles                                 # self-test of the particle validator
npm run near:deploy-contracts -- --network testnet       # build/deploy/verify all 6 Rust contracts (`res`, `deed`, `bounty`, `staking`, `dao`, `pilots`) + 4 protocol accounts (`--ensure-accounts`, `--redeploy`, or `--network mainnet --dry-run`)
npm run near:build-contracts                             # build release wasm32-unknown-unknown binaries inside backend/near-contracts (--cfg near)
npm run near:test-contracts                              # 85/85 Rust smart-contract unit tests across all 6 crates
```

Automated test suites: `npm test` (unit tests), `npm run test:integration` (Postgres integration), `npm run test:contract` (NEAR contract ports), `npm run test:parity` (engine parity), `npm run e2e` (Playwright headless-Chrome wave suites). Verify UI changes by loading the pages in a browser.

Vite `root` is `frontend/`; the 3D render engine used by two or more apps lives in `frontend/render/` (alias `@terra/render/*`); code used by frontend and backend lives in top-level `shared/{contracts,config,db,ledger,sim}`, test suites in `tests/{e2e,scenarios}`. Root directory layout follows the clean root rule (D-41): 6 domain directories (`backend/`, `frontend/`, `infra/`, `scripts/`, `shared/`, `tests/`) plus `README.md`, `HACKATHON.md`, agentic files, git, `LICENSE`, and `package.json`. Architecture limits and layering: `AGENTS.md` §6.

Adding a page: create the HTML, add it to `rollupOptions.input` in `frontend/vite.config.ts`, link it from `frontend/index.html`, and load scripts with `<script type="module">`.

## Rules to remember

- **UI chrome follows the design system** (`frontend/design/css/tokens.css` + `base.css`): `--ta-*` variables, chamfered plates (no `border-radius`), orange for action/selection, blue for systems, void text on orange (never white), Chakra Petch / IBM Plex fonts. The 3D scene follows the pillars in `AGENTS.md`, not the UI palette.
- **Any kitbash model change:** run `npm run validate:models -- <id>` (skill `model-geometry-validator`; must be 0 errors and 0 warnings, which includes colour roles, separation between functional groups and surface detail) and `npm run test:models` if you touched the validator. `/playground.html?inspect=<id>&validate=1` (or `V`) outlines the offending parts.
- **Any 3D model, particle preset, or shader change:** activate the matching skill from the `AGENTS.md` routing table, validate particles with `npm run validate:particles -- --all` (`npm run test:particles`), and verify in `/playground.html?inspect=<id>` (plus `&work=1&workTarget=<kind>`, `&depositStage=full|half|depleted`, `&lights=1` when relevant) across iso/front/side/top. Require `minY 0.000` (or `-0.100` for a building's sunk foundation-plinth skirt; the panel shows `✔`) and under 3.5k triangles (all archetypes are under 3.5k; several have < 1 % headroom).
- **Game flow QA:** `/play.html?planet=dune|oceanForest|forestRock&skip=1` jumps straight into the prototype gameplay; `/play.html?scenario=w00` runs the online flow (server sim), `?host=local&scenario=w00` the browser-only engine. Debug handles: `window.__game`, `window.__pg`, `window.__online`.
- **Dev tools & Visual Shader Lab (`F8`):** URL parameters (`?daynight=1|0`, `?shadow=1|0`, `?crt=1|0`, `?wind=1|0`, `?water=1|0`, `?perf=1|0`, `?scale=`, `?fps=`, `?focusRing=`), dev console commands (`` ` `` key: `help`, `warp`, `time`, `spawn`, `grant`, `stage`, `away`, `back`, `offerTruce`, `chain.ping`, `near.ports`, `near.quote`), `F8` Visual Shader Lab tabs (`CRT`, `PIXEL`, `SHADOW`, `DAY/NIGHT`, `WIND`, `WATER`, `PERF`), dev pages (`/dev/economy-sim/`, `/dev/chain/`, `/dev/parity/`), env variables (`PLANET_DAY_HOURS`, `PLANET_TIME_SCALE`, `NEAR_*`), and debug handles are documented in [`README.md`](./README.md) and [`infra/.env.example`](./infra/.env.example). Update both in the same commit when adding or changing one.
- **Authoritative planetary solar clock:** planet time (`timeOfDay` `0..24h`, `realHoursPerDay`, `timeScale`) lives in `shared/sim/src/systems/time/` (`blobs.planetTime`, `getPlanetTime`, `computePlanetTimeAtTick`, `setPlanetTime`, `dev.time`) and syncs bidirectionally with `frontend/render/core/dayNightConfig.ts` via `frontend/game/app/online/dayNightSync.ts` across both `?host=local` and multiplayer `PlanetHost`.
- **Building placement is one shared function (D-37):** `evaluatePlacement` (`shared/sim/src/systems/construction/placement.ts`, tile meaning in `grid/geo.ts`) is called by the `placeBuilding` handler (server and `?host=local` Worker) and by the client ghost (`frontend/game/features/hub-placement/GhostEvaluator.ts` only adapts replica data). Trees, rock, water, slope, hole, ridge and deposits are `terrain_unbuildable` until the player terraforms them; the client never mutates state, it sends one `placeBuilding` and shows the host's reject. Change a placement rule only there, and run `frontend/game/features/hub-placement/placement-parity.spec.ts` + `shared/sim/test/systems/placement-rules.spec.ts`.
- **W02 economy rules (D-42):** economy buildings are placed by `evaluatePlacement` and built on site by the HQ (later Builders) through the W01 `build` command (`systems/economy/buildJob.ts`, `dispatch/eligibility.ts`), orders pay progressively through `systems/queue/`, refunds clamp at the storage cap, and day/night derive from the solar clock (`systems/time`). A later wave extends these; it does not add a second path.
- **Units never teleport (SIM-M-01):** bot input is a unit command (`move`, `stop`, `die`, `attack`, `build`, `terraform`; `issueUnitCommand` or a work provider in `shared/sim/src/systems/units/registry.ts`). Units walk via the movement orchestrator → pathfinding service → locomotion, the only writer of `x/y/q/r`; the sim lint enforces it. Test with `shared/sim/test/units/*.spec.ts`. See `shared/sim/README.md` → Units.
- **Planet ground is generated once, in the sim (D-38):** `shared/sim/src/gen/world/` (orchestrator + stages, profile rows in `shared/sim/src/data/worldgen.ts`). `height` is metres and the renderer draws it as is; hidden layers (`FieldDef.hidden`, e.g. `subDeposit`) never leave the host: send clients `snapshot(s, { forClient: true })` / `diffSince(s, t, { forClient: true })`. Tile stamps go through `touchTile` / `stampTile` (they keep the per-sector `changedAt` index of `grid/sectors.ts` that `diffSince` uses). Changing generator output: bump `GEN_VERSION` (`gen/generators.ts`).
- **Who is where, and where to land (D-39):** read positions through `shared/sim/src/world/presence.ts` (`colonyPresence`, `faunaPositions`, `entitiesNear`, `presenceView` for AI); landing sites only through `nextLandingSite` / `landingBlock` (`world/landingPlanner.ts`). Landings are recorded forever in `blobs.landingHistory`; never land within `minLandingSeparation` of one. New entity kinds call `registerPresenceRole`.
- **Architecture limits:** no file over 500 lines, no function over 100 lines, no copy/paste, orchestrator classes compose small parts (details and layers in `AGENTS.md` §6). Run `npm run check:structure` after every refactor; `npm run build` runs it too.
- **Clean root folder rule (D-41):** the repository root holds ONLY agentic files (`.agents/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`), [`README.md`](./README.md), [`HACKATHON.md`](./HACKATHON.md), git files (`.git`, `.github/`, `.gitignore`), `LICENSE`, `package.json` (`package-lock.json`), and the 6 domain directories (`backend/`, `frontend/`, `infra/`, `scripts/`, `shared/`, `tests/`). Outward-facing game/protocol specs live in [`frontend/whitepaper/whitepaper.md`](./frontend/whitepaper/whitepaper.md) (`node frontend/whitepaper/render.mjs`) and [`README.md`](./README.md). Keep the repo root free of loose `.md` and configuration files.
- **NEAR 11-port, 6-contract & `TerraAgent Protocol` architecture:** `backend/app/src/near/` binds all 11 NEAR ports across `NEAR_MODE=mock|testnet|mainnet` (`mainnet` gated by `NEAR_ALLOW_MAINNET=1`) backed by 6 Rust `near-sdk 5.7` contracts (`backend/near-contracts/{res,deed,bounty,staking,dao,pilots}`, `85/85` Rust unit tests via `npm run near:test-contracts`, built via `npm run near:build-contracts` so `.cargo/config.toml` `--cfg near` stays active) and 4 core accounts (`<root>`, `protocol.<root>`, `relayer.<root>`, `minter.<root>`). `GET /v1/near/protocol` exposes the live `TerraAgent Protocol` schedule (`NEAR_PLATFORM_FEE_BP=100`, `NEAR_STAKER_PLATFORM_FEE_BP=50`, `NEAR_DAO_FEE_SHARE_BP=2000`, `NEAR_STAKER_MIN_NEAR=10`, `NEAR_PROTOCOL_STAKING_YIELD_BP=2000`, `NEAR_ESCROW_SLASH_PROTOCOL_BP=1000`) plus live RPC balances on `testnet`/`mainnet`. Set `NEAR_USE_PILOTS_FACTORY=true` so `relayer.<root>` provisions `{pilot}.pilots.<root>` while `NEAR_ROOT_SECRET_KEY` remains in cold storage; `claimAccount` performs atomic `[AddKey(userKey), DeleteKey(custodialKey)]` non-custodial rotation.
- Other people or agents may edit this repo at the same time (e.g. `frontend/render/ui/crt.ts`). Re-read a file before editing it and don't revert changes you didn't make.
- This is a git repository (`main`). Commit only the files you changed: other people's work is often uncommitted in the same tree.
- **Validate the wave (`"validate the wave"`):** whenever the user asks to **"validate the wave"** (or **"validate wave"**, **"validate WNN"**, **"review the wave"**), read and activate [`.agents/skills/wave-landing-validator/SKILL.md`](./.agents/skills/wave-landing-validator/SKILL.md), run `npm run validate:wave` (auto-detects the current wave worktree or open wave; or pass `<NN>`), execute its **mandatory 2-iteration review-and-fix protocol** (enforcing full Test Pyramid coverage [unit + integration + backend E2E + pos/neg/corner cases], eliminating AST function/block duplication, splitting new logic across thin orchestrators and focused services/parts, verifying client + server + shared sim parity, and passing `npm run validate:wave -- <NN> --gates`), and output the 6-part structured summary.
- **Wave build, landing & main sync:** when the user tells you **"merge wave into main"** (or **"land wave into main"**) or **"merge main into wave"** (or **"sync main into wave"**), immediately activate [`.agents/skills/wave-land-and-sync/SKILL.md`](./.agents/skills/wave-land-and-sync/SKILL.md) (`npm run wave:land -- NN` for Mode 1, `npm run wave:sync -- NN [--sync-issues]` for Mode 2).
